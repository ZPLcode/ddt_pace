# DDT D1 data collection and identification

The D1 task uses `assets/d1/robot.urdf` and its repository-local meshes. The
asset matches the D1 description in `go2_rl_robotlab/resources/d1/`, with mesh
paths rewritten to load within this repository. It identifies twelve leg joints;
the four wheel joints are excluded from the position objective.

## Configuration

| Setting | Value |
|---|---|
| Task | `Isaac-Pace-D1-v0` |
| Physics timestep | 0.0025 s / 400 Hz |
| Leg PD | Kp=60, Kd=2 |
| Nominal simulation effort limit | 90 N·m |
| Delay model | `command` |
| Identification parameters | 12 armature, 12 viscous friction, 12 friction, 12 bias, 1 delay |
| Default optimization budget | 4096 candidates, up to 200 iterations |

Joint order is FL, FR, RL, RR; each leg contains hip, thigh, calf. Code maps this
order to the simulator by joint name. Fit configurations store the selected URDF
hash, joint order, timestep, delay model and training records.

To select another asset, set `PACE_D1_URDF` to its URDF path. Changing the model
requires new identification and regenerated geometry headers. `fit.py --checkpoint`
rejects a checkpoint fitted with a different URDF.

## Excitation trajectory

The recordings comprise trajectory A and two versions of trajectory B. Each
recording is fitted independently with zero and free bias. The handover reports
fitted parameters and errors on the fitting record; policy and robot-task tests
remain pending.

| Name | Recording under `data/d1_real/` | Frequency range |
|---|---|---|
| A | `chirp_20260924_073552.pt` | 0.1–2 Hz |
| B (4 Hz) | `chirp_20260921_111227.pt` | approximately 0.1–4 Hz |
| B (10 Hz) | `chirp_20260921_105129.pt` | approximately 0.1–10 Hz |

Both B recordings use small-amplitude sweeps near a folded-leg pose. Their
maximum hip/thigh/calf amplitudes are 0.08/0.12/0.12 rad for the 4 Hz version and
0.08/0.08/0.08 rad for the 10 Hz version. The latter reduces amplitude at higher
frequencies and uses a slightly different calf center. B's frequency ranges are
estimated from the recorded targets.

The handover document lists the experimental methods and independent fitting results:
[D1 PACE 工作交接说明](d1_pace_work_report.md).

Trajectory A is a 20-second quadratic 0.1–2 Hz chirp sampled at 400 Hz. All legs
move together with mirrored left/right hip targets and opposite front/rear
thigh/calf excitation signs.

| Joint | Maximum configured amplitude |
|---|---:|
| hip | 0.18 rad |
| thigh | 0.95 rad |
| calf | 0.70 rad |

Front-leg centers are hip ±0.33, thigh −0.20, calf −1.80 rad. Rear-leg centers
are hip ±0.33, thigh 2.20, calf −1.80 rad. A frequency-dependent amplitude
reduction and smooth start/end transitions reduce speed and tracking demands.

The collector's runtime guard uses joint frames and mesh envelopes generated
from the URDF to check the chassis midline. Regenerate its header after changing
the asset:

```bash
python assets/d1/generate_geometry.py
```

## Hardware collection

Support the chassis securely with all wheels clear of the support and ground.
Run the wrapper on the robot with the installed D1 driver under `/usr/local`:

```bash
./scripts/pace/run_d1_hardware_chirp.sh --check
./scripts/pace/run_d1_hardware_chirp.sh
```

`--check` compiles and links only. The recording command folds the legs,
settles at A's center, records the chirp and returns. Recording stops
`d1_command.service` and `d1_bringup.service`, then rejects any remaining
`ros2_control_node`.

During gain handoff the collector preserves measured holding effort with a
temporary target, then blends back to the trajectory center before recording.
Motion checks cover joint range, stale/invalid feedback, velocity, torque,
tracking error and the generated leg-side guard. Recording limits include
4 rad/s speed, 20 N·m feedback torque and 0.32 rad tracking error.

A successful recording contains 8000 CSV rows. The extended format records
angles, targets, motor timestamps, velocity, torque, host sample/send times and
chirp diagnostics. Matching `.log` files contain collection output.

## Convert data

Copy the CSV to `data/d1_real/` on the identification machine:

```bash
python scripts/pace/d1_csv_to_pt.py data/d1_real/RECORDING.csv
```

The converter accepts complete legacy 8000×25 and extended 8000×66 recordings.
It checks finite values, monotonic host time, sample gaps and grid drift, then
resamples angles and targets onto the 400 Hz grid. It preserves the raw timing
and extended diagnostics. The generated tensors include `time [T]`,
`dof_pos [T,12]`, `des_dof_pos [T,12]` and explicit joint-order metadata.

## Fit parameters

Use the Isaac Lab Python environment and pass an explicit recording:

```bash
python scripts/pace/fit.py --task Isaac-Pace-D1-v0 \
  --data-file data/d1_real/RECORDING.pt --num_envs 4096 --headless
```

Run the command separately for each recording to keep one parameter set per
experiment. Each candidate starts from the measured initial pose with zero
initial velocity and empty delay history. The objective is the time-averaged
sum of squared joint errors.

`--fixed-zero-bias` removes the twelve bias coordinates from the search and
retains a 49-value checkpoint with zeros in those positions. `--max-iterations`
overrides the iteration budget. Outputs are under `logs/pace/d1_sim/`.

Each saved iteration contains matching `mean_NNN.pt`, `best_params_NNN.pt` and
trajectory files. `config.pt` records data and model metadata. Use matching
iterations when plotting a sampled candidate:

```bash
python scripts/pace/plot_trajectory.py --help
```

## Replay fitted parameters

Execute the recorded targets with a saved parameter vector:

```bash
python scripts/pace/fit.py --task Isaac-Pace-D1-v0 --headless \
  --checkpoint logs/pace/d1_sim/RUN/mean_NNN.pt \
  --data-file data/d1_real/RECORDING.pt
```

The same entry point checks the URDF, joint order and timestep, then runs the
recorded trajectory with the selected parameters. It saves simulated joint
positions and overall/per-joint RMSE for plotting. Replaying the fitting record
reports its fitting error; it does not establish policy or robot-task performance.

Plot the saved replay using the original plotting entry point:

```bash
python scripts/pace/plot_trajectory.py --replay-file PATH_TO_REPLAY.pt
```

The PACE score is the time average of the sum of twelve squared joint errors;
overall joint RMSE is `sqrt(score/12)`. Delay is applied as an integer number
of physics steps. Bias affects the encoder-to-physical-angle relationship and
must use the same convention in initialization, feedback and observations.

Data, fitted parameters, replay figures and logs remain local and should be
backed up separately.
